# NISAR GCOV site check (catalogue-only, run 2026-11-13)

Generated by `scripts/site_check.py` (re-run: `python scripts/site_check.py`).
Data: ASF catalogue (`asf_search`, platform NISAR, processingLevel GCOV, start >= 2026-06-17) and CMR (OPERA DSWx, metadata only). **Nothing was downloaded.**
Outputs: `data/catalog/pass_counts.csv` (428 scene rows, 13 AOIs), `data/catalog/aoi_ranking.csv` (per track/direction/frame stack), `data/catalog/dswx_counts.csv`.

Method: each AOI is a 0.225 deg box (~25 km). A stack = same track + direction + frame, counted only where the footprint covers >= 90 % of the AOI and the date is outside the gap 2026-07-27..2026-08-10 (4 scenes fell inside it and are flagged `in_gap=True`). Repeat interval is 12 days, so most stacks have 9-12 usable passes.

The "before/after split" uses a **climatological seasonal flood-timing hypothesis**, not an observed event. Every area below is **event unconfirmed**.

## What I could NOT verify

- **Flood events**: none confirmed. No event database or imagery was checked. All split dates are climatological guesses, so mark every area **event unconfirmed**. A real check needs DSWx/GCOV pixels or an event source such as GDACS, Copernicus EMS or DFO.
- **Quality**: the `quality` column is only processing metadata (production config PR, CRID, PGE version, product version 1.0.x, MOE orbit, full frame). QA_REPORT.pdf and QA_SUMMARY.csv files exist per granule but were not downloaded. Calibration status and RFI were not checked.
- **Processing consistency**: stacks mix CRID P05023 (PGE R05.02.3) with the newer P05036 (R05.03.2) on the latest 1-2 dates. Radiometric consistency across the two versions is unverified.
- **Exact AOI coverage**: computed from catalogue footprint polygons, not from valid-data masks. Edge nodata or layover is unchecked.
- **Land cover** (forest/wetland) comes from site knowledge, not from a land-cover layer.
- **Downloadability / size**: sizes come from catalogue `bytes`. Access was not tested.
